## 1. Local Services & Data

- **Services / database:** On-phone Dart services and SQLite (`sqflite` suggested) handle all app operations. Store images in persistent app-local files. No hosted backend, accounts, cloud backup, or cloud inference in the current scope.
- **MVP operations:** Recognize an image and return an editable receipt draft; atomically save a confirmed receipt and purchase lines; list local receipts/products; return dated supplier comparisons/history; calculate restock and selling-price estimates. Exact method names/types: TBD.
- **Initial entities:** Products and Suppliers are reusable identities. Receipts reference suppliers; purchase lines reference receipts and products, preserving original descriptions, confirmed quantities/pack conversion, net amounts, and unit costs. Each purchase is separate, including same-day purchases. Follow the provisional entities in project scope.
- **Rules / validation:** Require confirmation of unresolved fields. Match the exact brand/variant/size; never silently merge different products. Validate quantities and amounts before calculating unit costs. Keep earlier purchases; compare supplier changes against the previous purchase at that supplier. Resolve ambiguous same-day ordering explicitly. All operations work without login or internet.

## 2. Services & Setup

- **On-device OCR:** Suggested `google_mlkit_text_recognition` bridges to native ML Kit on the phone. Verify bundled model configuration and offline availability before first use. OCR supplies text/positions; implement receipt parsing and confirmed product matching separately in Dart.
- **Configuration:** No API keys, server URLs, or account configuration required. Bundle required model assets and configure native permissions. App path and demo device: TBD.
- **Local setup:** App path/setup commands TBD until scaffolded. Use Flutter dependencies, native camera setup, bundled OCR, versioned SQLite migrations, and persistent image storage (`image_picker`/`path_provider` suggested). Development dependency downloads are separate from offline app runtime.
- **Example calls:** TBD until operations exist. Provide runnable Dart examples or focused integration checks for image → draft → confirmed save → comparisons → calculations. Local services do not need HTTP endpoints.

## 3. Build Instructions

- Inspect existing code, preserve unrelated changes, and build only MVP local services/integrations. Refine the schema as needed; keep OCR, receipt parsing, models, calculations, and local storage separate.
- Enforce purchase validation at the local service/database boundary. Keep receipt content out of routine logs; make repeated saves safe from duplicate records. Surface possible duplicate receipt imports for confirmation.
- Define exact interfaces in Dart models/services and local database migrations. Preserve price/quantity snapshots per purchase. Use consistent money units and rounding; handle net amounts/discounts without counting discounts twice.
- Compare latest recorded purchase prices per supplier with dates visible; historical minima remain a separate view. Missing prices, pack sizes, or availability remain unknown. Restock calculations respect whole packs and show owner-entered extra costs; do not claim guaranteed current prices or maximum profit.
- Suggest suppliers for selected products using the latest comparable records and group the list by supplier. Show estimated totals and the data's dates; separate product-price savings from travel/delivery costs. Mark selling-price outputs as estimated gross profit, with adjustable markup.
- Preserve receipt images in persistent app storage before saving their references. Use a database transaction for each confirmed receipt and its lines; handle file or transaction failures without leaving saved records pointing to missing images. Preserve earlier purchases during local database migrations.
- Resolve missing interface details before frontend use. Coordinate caller-visible changes directly and update affected code/fixtures together.
- Provide working operations and setup examples; frontend work handles client wiring. Install the app and disable internet before first launch to prove bundled OCR works without a model download. Then verify confirmed saves and images survive restart and appear in comparisons/calculations.
- Summarize changes, setup, checks, and blockers. Run `flutter analyze` and appropriate focused tests once code exists. Distinguish service-only/static checks, connected local storage, and real-device offline OCR results.
