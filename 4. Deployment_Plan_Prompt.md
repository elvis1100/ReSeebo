# Offline App Build & Demo Plan

*Complete this before the final build and demo. Use [1. Project Scope](1.%20Project_Scoping_Prompt.md). Reseebo is a fully offline Flutter app; deployment means building and installing it on the demo phone.*

## 1. Demo Target

- **Target OS / phone:** TBD (Android or iOS; confirm before configuring the build).
- **App path / package ID:** TBD until scaffolded.
- **Distribution:** Installable app artifact appropriate to the selected OS. No frontend, backend, or database hosting required.
- **Submission requirements:** Confirm whether judges need an installable artifact, repository, demo video, or other materials. If a live URL is required, resolve that with the team before submission; the mobile workflow remains offline.

## 2. Bundled Resources & Local Storage

- Bundle required OCR models, fonts, and assets. No first-launch model download or runtime network call.
- Store the local store profile, products, confirmed product aliases, suppliers, receipts, and purchase lines in SQLite. Preserve original receipt images, optional product photos, and store photo/logo in persistent app-local files.
- No accounts, API keys, server URLs, or cloud backup configuration.
- Development dependencies and build tools may require internet during setup; the installed app must work without it.

## 3. Build & Install

- **Setup:** From the app root, run `flutter pub get` while development dependencies are available.
- **Checks:** Run `flutter analyze` and appropriate focused tests once code exists.
- **Android, if selected:** `flutter build apk --release`; install the generated APK on the demo phone.
- **iOS, if selected:** Build and signing require macOS/Xcode; document the actual signed-device build/install steps.
- **Artifact / installation steps:** Record the actual artifact path and commands after the app is scaffolded and built.

## 4. Offline Acceptance Check

1. Install the app, then disable internet before its first launch. Avoid a warm-up launch that could hide model-download requirements.
2. Capture/import a real receipt, review unresolved fields, confirm product matches, and save it.
3. Save a store name/default markup, product photo, and confirmed alias; restart the app. Check these details along with the saved receipt, original image, and purchase lines.
4. Compare the same product across two suppliers and repeated purchases; verify dates, unit costs, and suggested selling prices. Check store-default and product-override markup, including 0%.
5. Optionally enter a restock quantity or adjust pricing on the comparison screen and verify estimates offline. Check that settings changes do not rewrite earlier purchase costs.
6. Check camera denial, unreadable input, and duplicate-save handling without losing saved data.

## 5. Demo & Handoff

- Prepare real receipts and earlier purchases for the comparison; keep fixture UI separate from verified OCR and storage results.
- Record a short demo with internet disabled and keep the tested artifact available for reinstalling.
- Report static checks, local storage checks, real-device offline OCR, and build/signing results separately. Record remaining blockers honestly.
