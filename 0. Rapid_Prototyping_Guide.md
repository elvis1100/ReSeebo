# Rapid Prototyping Guide
*Workflow for a 3-person team using AI Coding Agents in a 24-hour Hackathon.*

### Phase 1: Ideation & Scoping (Hours 1 - 2)
*Goal: Decide what to build, define the MVP, and divide responsibilities.*

1. **Brainstorming & Selection (30 mins):**
   - Once the topic is given, pitch 3-5 ideas.
   - Select the idea that maximizes "Wow factor" while remaining highly feasible for a 24-hour window.

2. **Scope the MVP (Minimum Viable Product) (45 mins):**
   - Identify the 2-3 core features necessary to prove your concept. Cut everything else.
   - Draft the "happy path" user flow.
   - Complete [1. Project Scope](1.%20Project_Scoping_Prompt.md). Keep data entities provisional; a full schema is not needed yet.

3. **Role Assignment (15 mins):**
   - **Person A (Product/Pitch):** Focuses on user journey, wireframing, pitch deck, demo video, and testing. Generates design assets using AI.
   - **Person B (Frontend Builder):** Uses AI agents to rapidly generate UI components, screens, and state management based on wireframes.
   - **Person C (Local Services/Integration):** Uses AI agents to build on-device OCR integration, receipt parsing, SQLite storage, and calculation services.

### Phase 2: System Architecture & Agent Setup (Hour 3)
*Goal: Agree on enough initial context for both builders to start.*

1. **Define the Stack:** For Reseebo, use Flutter/Dart, local SQLite, bundled on-device OCR, camera/gallery capture, and persistent local image files. Verify OCR on the demo phone with internet disabled early.
2. **Agree on the Starting Interfaces:**
   - Fill in the initial integration plan in [1. Project Scope](1.%20Project_Scoping_Prompt.md).
   - Identify the first local operations, expected inputs/results, and failure behavior needed to start. Reseebo needs no account or sign-in.
   - Leave unknown details as TBD and refine the database schema during backend implementation. Resolve shared-interface blockers before either side depends on them.
   - Keep screens and local services in separate feature/layer folders; coordinate edits to shared code.
3. **Complete the Role Briefs:** Use [1.1 Frontend](1.1%20Frontend_Prompt.md) for Person B and [1.2 Backend/Integration](1.2%20Backend_Integration_Prompt.md) for Person C. Both use number 1 as kickoff context; no separate shared blueprint is required.
4. **Repo Setup:** Initialize Git, set up the skeleton, ensure access for all team members, and use separate branches or worktrees for concurrent builders.

### Phase 3: The Build Sprint (Hours 4 - 18)
*Goal: Head-down execution using AI agents.*

- **Frontend Workflow (Person B):** Feed the scope, frontend brief, and wireframes to the AI. Build screens with a separate local data adapter. Use mocks matching the initial agreement until real operations are available, then inspect their implemented interfaces.
- **Local Services Workflow (Person C):** Feed the scope and local services/integration brief to the AI. Refine the SQLite schema, implement agreed operations, and provide setup instructions, code paths, and verified examples.
- **Early Integration:** Connect the first real user journey as soon as its operation is ready. Person B wires the client; Person C coordinates integration verification. Do not wait until both sides finish.
- **Integration Syncs:** Integrate feature by feature and review blockers every 3-4 hours. Communicate interface changes directly, updating affected code and fixtures together. Give a short handoff summary; no shared Markdown change log is required. Revisit the scope only for material product/MVP changes.
- **QA (Person A):** Test early and often to find critical bugs.

### Phase 4: Polish & Demo Prep (Hours 19 - 22)
*Goal: Stabilize and record.*

1. **Feature Freeze:** Stop adding new features. If it's not in by hour 18, it's cut.
2. **Bug Squashing:** Use AI to fix visual bugs, error handling, and loading states.
3. **Record Demo Video:** Record the "happy path" while the app is stable.

### Phase 5: Submission & Rehearsal (Hours 23 - 24)
*Goal: Submit and practice.*

1. **Finalize Repo:** Push final code and generate a stellar README using AI.
2. **Submit:** Submit all required materials before the deadline.
3. **Rehearse:** Practice the live 3-minute pitch for Demo Day.
